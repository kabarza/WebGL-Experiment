## 1. Current architecture

```
src/experiments/globe-1/
├── meta.ts          — slug/title/tags
├── params.ts        — defaults, presets, DialKit dial config (single source of truth)
├── index.ts         — re-export + HMR boundary
├── helpers.ts       — math (lat/lon, snap, grid polylines, snake path, beziers, springs),
│                      cross-texture, parseCountries, prefersReducedMotion, types/constants
├── marker.ts        — CountryMarker class (cross + label) + ensureLabelStyles

├── inline-editor.ts — DialKit Countries-folder DOM injection (gallery-only side-effect)
```

**Both entry points share everything from `helpers.ts` down through `scroll-pitch.ts`.** The split between gallery and standalone is now just (a) DialKit panel integration vs static baked params and (b) the gallery framework's lifecycle vs an in-line RAF loop.

## 2. Webflow embed contract

Generated by `src/lib/webflow-export.ts:27`:

```html
<div data-webgl-experiment="globe-1" data-flow-tempo
     style="position:relative;width:100%;aspect-ratio:1/1;min-height:320px;overflow:hidden;">
  <canvas style="display:block;width:100%;height:100%;"></canvas>
  <script src="https://webgl-experiments.vercel.app/exports/globe-1-v2.js"></script>
</div>
```

**Behavior the standalone now guarantees:**

- **Multi-instance.** `document.querySelectorAll('[data-webgl-experiment="globe-1"]')` boots one self-contained instance per wrapper. Pointer listeners are scoped to each `canvas` (not `window`), and pointer events are filtered by `pointerId` so two embeds on the same page don't cross-fire.
- **Zero-size resilient.** `resize()` early-outs when `rect.width < 1 || rect.height < 1`. The render loop early-outs when `renderer.domElement.width < 1`. Wrappers in `display:none` tabs, `height:auto` flex sections, or pre-paint CMS containers don't NaN the projection matrix; when the parent gains a real size, `ResizeObserver` fires and the canvas catches up.
- **Off-screen pause.** `IntersectionObserver` (rootMargin: 100px) flips an `inView` flag. RAF still loops (so resuming is instant), but the frame body early-outs while off-screen.
- **Reduced-motion friendly.** `prefersReducedMotion()` is read at boot; auto-spin and scroll-pitch are suppressed when the user has the OS setting on.
- **Per-deploy params.** `scripts/build-export.ts` continues to support `--params=<json>` and `--params-file=<path>`. Baked params override `controls.defaults` on a per-key basis.

**To re-build the export bundle for a new client deploy:**
```bash
npx tsx scripts/build-export.ts --experiment=globe-1 --version=2
# or with custom params:
npx tsx scripts/build-export.ts --experiment=globe-1 --version=2 --params='{"scrollPitchEnabled":true,"basePitchDeg":15}'
```

## 3. Performance — what we now have, what to watch

### 3.1 Hot-path allocations: gone
- `SnakeController.update()` no longer allocates a `Float32Array(N*3)` per frame for vertex colours — it uses `colorScratch` field, resized in lockstep with `scratch` whenever `setTrailDetail` changes the count.
- `SnakeController.sampleAt(d, out)` is now mutating; the callers (the snake update loop, `sampleHeadAndTangent`) pass scratch Vector3s.
- `CountryMarker.updateFlash()` uses three scratch `THREE.Color` instances (`_baseCol`, `_accentCol`, `_lerpCol`) instead of `new THREE.Color()` per marker per frame.
- `SnakeController.setAccentColor(hex)` mutates `material.color` in place.
- The snake-icon path reuses `_iconHeadNDC`, `_iconTipNDC`, `_iconHeadView`, `_iconCenterView` scratch Vector3s and drops the unnecessary `.clone()` before `.project()`.
- `SnakeController.prunePath()` runs every ~30 s in continuous mode so the path array doesn't grow unbounded.
- Skip-on-equality on `lineColor`, `lineOpacity`, `lineWidth`, `accentColor`, `snakeWidth`, `bgColor`, `fov`, `zoom` — no GL-state writes when nothing changed.
- `ensureLabelStyles` caches its three inputs and skips the `style.textContent` rewrite when they're unchanged.

### 3.2 Performance with more countries
The architecture is unchanged here vs v2; if you push past ~30 countries you'll start noticing:

| Scale | Bottleneck | Symptom |
|---|---|---|
| ≤ 30 (today) | none | 60fps everywhere |
| ~50–80 | per-marker visibility test in JS, per-marker materials | OK on desktop, light jank on mobile |
| ~100+ | **CSS2DRenderer projects every label every frame** | Dominant cost; jank on mid-tier Android |
| ~500+ | architecture mismatch | InstancedMesh + atlas labels needed |

**Recommendation:** add countries freely up to ~30. Past that, do **Item 11** from v2 (InstancedMesh + label pool + GPU occlusion). It's deferred — not done — because it's half a day of work that ossifies the architecture for no current benefit.

### 3.3 Wireframe perf note
The user iterated to `Line2`-per-polyline (one `Line2` per meridian/parallel) so `lineWidth` actually works and there are no end-cap dots at sub-segment joins. Cost: `lonSeg + latSeg − 1` `Line2` instances each rendering 64 sub-segment quads. At default 30×30 grid, that's 59 instances × 128 triangles ≈ 7.5K triangles for the whole wireframe — trivial.

## 4. Scroll-driven pitch (new feature)

Lives in `src/experiments/globe-1/scroll-pitch.ts`. Imported by both `experiment.ts` and `standalone.ts`.

**How it works:**
1. `createScrollPitchTracker(wrapper)` returns `{ currentPitch, update(dt, opts), dispose() }`.
2. When `opts.enabled` is `true`, it attaches **passive** `scroll` and `resize` listeners on `window`, computes a normalised viewport-intersection ratio for the wrapper (`(vh - rect.top) / (vh + rect.height)`), and maps `0..1` to `−rangeRad/2 .. +rangeRad/2`.
3. `update()` runs once per frame and exponentially filters `current` toward `target` (`smoothing` controls decay rate, default 8 1/s).
4. The tracker is dormant when `opts.enabled` is `false` — listeners are detached and `currentPitch` decays to 0. Toggling the dial knob attaches/detaches lazily.
5. `prefersReducedMotion()` is checked at construction; when active, the tracker stays at 0 regardless of `enabled`.

**Composition** in both `experiment.ts` and `standalone.ts`:
```ts
world.rotation.set(
  basePitch + pitchOffset + autoPitch + scrollTracker.currentPitch,
  baseYaw   + yawOffset   + autoYaw,
  0,
);
```
Drag, auto-spin, and scroll-pitch are independent additive terms — none disturbs the others.

**Dial knobs** (Scroll folder, collapsed by default):
- `scrollPitchEnabled: false` — flip on per page.
- `scrollPitchRangeDeg: 30` — total swing in degrees over the full intersection range. ±15° at default.
- `scrollPitchSmoothing: 8` — exponential decay rate 1/s; bump for snappier tracking.

For Webflow embeds, configure via `--params='{"scrollPitchEnabled":true,"scrollPitchRangeDeg":40}'`.

## 6. The DialKit DOM hack (still here, now version-pinned)

`inline-editor.ts` still uses `MutationObserver` + class-name lookups (`.dialkit-folder`, `.dialkit-folder-content`, `.dialkit-text-label`, `.dialkit-text-control`) to inject the country editor into the panel. This is the single biggest stability risk for a long-lived deploy.

**Mitigation today:** `package.json` now pins `dialkit` to **exact** `1.2.0` (no caret). `npm install` won't bump it; class names won't change.

**Long-term fix (deferred):** PR upstream adding a `type:'custom'` field to DialKit's config schema. Until then, any time you bump DialKit you must manually retest the country editor.

This only affects the gallery — `standalone.ts` doesn't import `inline-editor.ts` at all, so Webflow embeds are unaffected.

## 8. How to verify what shipped

```bash
# Type safety
npx tsc --noEmit                              # exits clean

# Export bundle (this rebuilds the Webflow IIFE)
npx tsx scripts/build-export.ts --experiment=globe-1 --version=2

# Gallery dev server
npm run dev                                    # http://localhost:5173/?exp=globe-1
```

**Manual smoke tests after a deploy:**
1. Two `<div data-webgl-experiment="globe-1">` blocks on a single test page → both initialize, dragging one doesn't drag the other.
2. Wrap an embed in `<div style="display:none">`, toggle visible after 2s → globe paints correctly when revealed.
3. Drop the embed into a parent with `height:auto` (Webflow flex section) → wrapper gets a 1:1 aspect with min-height 320px, doesn't collapse.
4. Scroll past the embed on a long page → DevTools Performance graph shows GPU usage drop.
5. macOS System Prefs → Accessibility → Reduce Motion ON → reload → auto-spin off, scroll-pitch off.
6. Set `scrollPitchEnabled: true` via baked params → scroll the page, globe pitches up/down smoothly.
