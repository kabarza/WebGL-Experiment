Overview

3 methods · 4 paths

The export system lets designers take a tweaked WebGL effect from our tool and drop it into Webflow with zero friction. Three export methods serve three workflows; once the effect is live, four customization paths cover everything from a one-line code edit to a full DialKit-in-Webflow session.

03

Webflow JSON Structure

paste format

When pasted into Webflow, the JSON creates a wrapper Div containing a Canvas and an HtmlEmbed with the full inline IIFE. Node IDs are fresh UUIDs each copy; Webflow remaps them on paste.

AComponent shape

Div Block (wrapper)
  ├── Canvas (100% × 100%, data-flow-tempo attribute)
  └── HtmlEmbed (<script> with full inline IIFE)

BPaste format

The paste format is @webflow/XscpData. The structure is roughly:

json{
  "type": "@webflow/XscpData",
  "payload": {
    "nodes": [
      { "_id": "<wrapper-uuid>",
        "type": "Block", "tag": "div",
        "children": ["<canvas-uuid>", "<embed-uuid>"] },
      { "_id": "<canvas-uuid>",
        "type": "DOM", "tag": "div",
        "data": {
          "tag": "canvas",
          "attributes": [{ "name": "data-flow-tempo", "value": "" }]
        } },
      { "_id": "<embed-uuid>",
        "type": "HtmlEmbed",
        "v": "<script>…full inline IIFE…</script>" }
    ],
    "styles": [
      { "_id": "<canvas-style-uuid>",
        "type": "class", "name": "Canvas",
        "styleLess": "width: 100%; height: 100%;" }
    ],
    "assets": [], "ix1": [], "ix2": { … }
  },
  "meta": { /* zeroed counters */ }
}

CResponsive vs fixed sizing

Responsive
Fills the parent

Canvas style is width: 100%; height: 100%;. Wrapper sizing is up to the Webflow layout.

Fixed
Explicit dimensions

Canvas style adds explicit pixel sizes, e.g. width: 800px; height: 600px;.

Inline IIFE Structure

self-contained

The JavaScript inside the Webflow JSON's HtmlEmbed is a fully self-contained IIFE. No external dependencies. CONFIG at the top, DIAL_CONFIG below, then the WebGL2 boot. 

javascript// =============================================
// Flowing — Flow Field v1
// =============================================
// Edit these values to customize the effect.
// Connect Webflow component properties to
// data-flow-ft-* attributes on the wrapper div.
// Set dialKit to true to load the visual editor.
// =============================================

const CONFIG = {
  // Colors (hex without #)
  bgColor: "0d0d10",
  color1: "492d7b",
  color2: "8c5a1c",
  highlightColor: "d4a0e8",

  // Noise
  noiseScale: 0.55,
  noiseSpeed: 0.037,

  // Flow Field
  warpStrength: 1.86,
  warpScale: 0.58,

  // … ~25 params total
  dialKit: false,
};

const DIAL_CONFIG = {
  "Noise Fill": {
    noiseScale:  [0.55, 0.01, 5, 0.01],
    noiseSpeed:  [0.037, 0, 1, 0.001],
  },
  // … one folder per group
};

(function () {
  var wrapper = document.querySelector("[data-flow-tempo]");
  if (!wrapper) return;
  var canvas = wrapper.querySelector("canvas");

  // ── Params: data attributes override CONFIG ──
  var P = {};
  for (var key in CONFIG) {
    P[key] = CONFIG[key];
    var kebab = key.replace(/([A-Z])/g, "-$1").toLowerCase();
    var attr = wrapper.getAttribute("data-flow-ft-" + kebab);
    if (attr !== null) {
      P[key] = typeof CONFIG[key] === "number" ? Number(attr) : attr;
    }
  }

  // ── Optional DialKit loading ──
  if (P.dialKit === true) {
    var s = document.createElement("script");
    s.src = "https://webgl-experiments.vercel.app/exports/dialkit-standalone.js";
    s.onload = function () {
      window.FlowDialKit.create(P, DIAL_CONFIG, function (updated) {
        for (var k in updated) P[k] = updated[k];
      });
    };
    document.head.appendChild(s);
  }

  // WebGL2 init, shader compile, ResizeObserver,
  // pointermove, render loop reading from P every frame…
})();

▸Param priority

When the standalone script initializes, params resolve top-down:

data-flow-ft-* attributes highest
↓
CONFIG block editable
↓
Baked defaults fallback

This gives users three levels of control without any conflicts. Webflow Component Properties win, the visible CONFIG block is the daily edit surface, and the IIFE always has a working fallback if something is missing.

Data Attribute Convention

~25 params

All customizable params can be set via data attributes on the wrapper div. The standalone JS reads these at init time and overrides CONFIG values. Auto-derived from the experiment's params.ts — no manual mapping needed.

ANaming rules

Prefix
data-flow-ft-

Same prefix everywhere, regardless of experiment.

Format
kebab-case

Derived from the camelCase param name. warpStrength → warp-strength.

Colors
hex, no #

e.g. "492d7b". The hex2rgb helper accepts both forms at runtime.

Numbers / booleans
string form

Parsed via Number() for numbers; "true"/"false" for booleans.

DialKit in Webflow

live tweaking

DialKit can be loaded inside a Webflow site for live parameter tweaking. Off by default — the designer enables it by setting dialKit: true in CONFIG or data-flow-ft-dial-kit="true" on the wrapper div.

AHow it works

  1. The standalone script detects dialKit === true.
  2. It dynamically loads dialkit-standalone.js from the CDN.
  3. The bundle contains React + ReactDOM + DialKit pre-packaged with a vanilla JS API.
  4. It creates the floating DialKit panel with all controls from DIAL_CONFIG.
  5. Param changes update the live P object — the render loop picks them up immediately.
  6. A Copy Config button copies the current values as a formatted CONFIG block.
  7. The designer pastes the new CONFIG over the old one in the HtmlEmbed to persist changes.

BStandalone bundle

A pre-built bundle hosted at https://webgl-experiments.vercel.app/exports/dialkit-standalone.js.

Contents
~120–150 KB gzipped

React + ReactDOM (production) · DialKit library + styles · vanilla JS API wrapper. Acceptable size — loads only when explicitly enabled, cached after first load.

Exposed API
window.FlowDialKit

create(params, config, onChange) — mounts the panel, mutates params in place, calls onChange on every change.

javascriptwindow.FlowDialKit = {
  /**
   * Create a DialKit panel connected to the experiment params.
   * @param params    - Live params object (mutated in place by DialKit)
   * @param config    - DialKit folder config with ranges
   * @param onChange  - Called whenever a param value changes
   */
  create(params, config, onChange) { /* … */ }
};

Build script: scripts/build-dialkit-standalone.ts — uses Vite library mode to bundle React + DialKit into a single IIFE with the window.FlowDialKit global.

CCopy Config button

The Copy Config button appears in the DialKit panel footer. When clicked, it copies the current params formatted as a drop-in CONFIG block:

javascriptconst CONFIG = {
  bgColor: "0d0d10",
  color1: "492d7b",
  color2: "8c5a1c",
  // … all params with current values
  dialKit: false,
};
Note dialKit is always set to false in the copied CONFIG. The designer re-enables it manually if they need to tweak again. This prevents DialKit from loading on the published site.

Post-Export Customization Paths

4 paths

After export, designers can customize the effect four different ways depending on the team and the task — from a one-line CONFIG edit to a full live-tweak DialKit session running inside the Webflow page itself.

Path 1

Edit CONFIG directly

Open the HtmlEmbed code in Webflow Designer, find the CONFIG block at the top, change values. Simple and immediate.

Path 2

Webflow Component Properties

Bind data-flow-ft-* attributes to Component Properties. Webflow's property panel then shows named inputs that non-technical team members can adjust without touching code.

Path 3

Re-export from our tool

Return to our tool, tweak in DialKit, click Copy Config to grab updated values. Paste into the Webflow HtmlEmbed.

Path 4

DialKit in Webflow

Set dialKit: true. The floating control panel appears on the page. Tweak params live, then click Copy Config to persist. Set dialKit: false when done.

APer-experiment export generator

src/experiments/flow-field/generateExport.ts imports the experiment's shaders (Vite inlines them as raw strings at build time) and constructs the complete self-contained script.

ResponsibilityDetail
Shader importsVertex + fragment as raw strings.
InputsCurrent params (from DialKit) + dial config (from params.ts).
OutputA complete <script>…</script> string with header, CONFIG, DIAL_CONFIG, attr reading, DialKit loader, WebGL2 boot, render loop.
Color handlingStrips # prefix before embedding.
CompositionTemplate literals; shaders embedded verbatim; CONFIG comes from current DialKit state at export time.

The existing standalone.ts remains as the entry point for build-export.ts (hosted bundle builds). generateExport.ts is specifically for the inline Webflow JSON export path.

BWebflow JSON generator

src/lib/webflow-json.ts accepts the inline script string and sizing options, generates fresh UUIDs, and constructs the full @webflow/XscpData JSON.

  • UUID generation: crypto.randomUUID() with a fallback to a simple random hex generator for older browsers.
  • Script escaping: The inline script inside the v field and meta.html field needs proper escaping for JSON embedding — JSON.stringify handles this when building the outer JSON.
  • Returns: JSON as a string ready for the clipboard.

Implementation Phases

3 phases

Phase 1 gets the Webflow JSON paste working end to end. Phase 2 adds the live tweaking experience. Phase 3 scales the system to every experiment.

Phase 01

Core Export

The foundation. Gets the Webflow JSON paste working end to end.
  • Tabbed ExportPanel — Refactor from stacked sections to 3 tabs (Webflow JSON / HTML Embed / MCP). Shared version selector + sizing at top.
  • webflow-json.ts — New module generating the @webflow/XscpData JSON. Takes inline script + sizing, returns clipboard-ready string.
  • generateExport.ts for flow-field — New file that imports shaders and returns the full inline IIFE string.
  • CONFIG block generation — IIFE starts with a CONFIG block populated from current DialKit values. Colors stripped of #.
  • Data attribute reading — IIFE reads data-flow-ft-* attributes and overrides CONFIG. Auto-derives kebab-case from camelCase.
  • hex2rgb update — Support both #rrggbb and rrggbb formats.
  • Wire it up — ExportPanel's Webflow JSON tab calls generateExport() → generateWebflowJSON() → clipboard.
  • Update standalone.ts — Add data attribute reading so the hosted bundle (HTML Embed tab) also supports data-flow-ft-* overrides.
Phase 02

DialKit in Webflow

The live tweaking experience inside Webflow.
  • build-dialkit-standalone.ts — Bundles React + ReactDOM + DialKit + CSS + vanilla API wrapper into a single IIFE. Output: dist/exports/dialkit-standalone.js.
  • Vanilla API wrapper — window.FlowDialKit.create(params, config, onChange). Creates a React root, renders DialKit panel, wires up param syncing and Copy Config.
  • DialKit loading in IIFE — Inline script checks CONFIG.dialKit / data-flow-ft-dial-kit and dynamically loads the standalone bundle if true.
  • DIAL_CONFIG embedding — generateExport.ts includes the full dial config (folder structure with ranges) in the IIFE.
  • Copy Config (Webflow DialKit) — Button in panel footer. Copies current params as a formatted CONFIG block; always sets dialKit: false.
  • Copy Config (our tool) — Same button in our tool's DialKit panel. Same format, same behavior. Supports the "tweak in tool, paste in Webflow" workflow.
  • Host the bundle — Deploy dialkit-standalone.js alongside experiment bundles at /exports/dialkit-standalone.js. Add to Vercel config with appropriate cache headers.
Phase 03

Template & Multi-Experiment Support

Scale the system to all experiments.
  • Export template — Add generateExport.ts to the experiment template. New experiments get export support out of the box.
  • Update new-experiment.ts — Scaffold script generates generateExport.ts with placeholder shader imports and WebGL setup.
  • Shared export utilities — Extract common patterns (attr reading, DialKit loading, hex2rgb, ResizeObserver, mouse tracking) into helper strings that generateExport.ts files can compose from.
  • Update create-experiment.md — Document that new experiments need a generateExport.ts and what it should contain.

Color Format & Open Questions

decide later

Colors use hex without the # prefix throughout the export system. A handful of decisions can be finalized during implementation.

AColor format

ContextFormatExample
CONFIG block"492d7b"color1: "492d7b"
Data attributes"492d7b"data-flow-ft-color1="492d7b"
Copy Config output"492d7b"Same as CONFIG
Internal processingBoth acceptedhex2rgb handles with/without #

The hex2rgb helper in the IIFE strips # if present, so both formats work at runtime. This is for backward compatibility with existing hosted bundles that use #-prefixed colors in BAKED_PARAMS.

BOpen questions

Q1

Canvas class naming

Currently "Canvas" in the Webflow JSON. Should it be more specific (e.g. "WebGL Experiment Canvas") to avoid collisions with existing Webflow classes?

Q2

Multiple experiments per page

Current selector is [data-flow-tempo]. Should we use [data-flow-tempo="flow-field"] (slug as value) to support multiple different experiments on the same page?

Q3

Wrapper sizing — class or inline?

Should the wrapper div carry a class with sizing styles, or just inline styles? A class is cleaner for Webflow users to override; inline guarantees sizing works without class conflicts.

Q4

DIAL_CONFIG size

For experiments with many controls, DIAL_CONFIG could be large. Include it only when dialKit is enabled? Means users who later enable DialKit must re-export.

Q5

Script minification

Should the inline IIFE be minified? Smaller payload but harder to read/edit CONFIG. Could offer both — Copy JSON (readable) and Copy JSON (minified).
